# ARC 2.5 candidate: evidence and release gates

## Reconciliation of the ARC 2.4 live test

The Producer reported 27 negative typed-action checks, 24 local Terse checks,
six Working checks, invalid timestamp and correction/replay coverage, and one
automatic recovery. These are tester-reported results, not independent repeat
execution by the builder. The observer saw responsive polls, no new crash, and
normal public duty/work events. Private peer exchanges were not visible to it.

The report did not exercise the signed app's observation window. Its task was
honestly marked visually blocked before reassignment; later text completion is
not visual verification. The original 2.3 constraint-loop exception remains
unreproduced, although 2.4 removed implicated layout paths. Absence of a new
crash during CLI activity alone does not close the window acceptance gate.

The following report details need qualification:

- The listed packet kinds total nine, not eight.
- Section 18.13 already existed in 2.3; the 2.4 heading-only language update
  was not a new language feature.
- The observer did receive an unsolicited declaration and vocabulary question.
  Non-declaration structured packets require mutual agreement, but ordinary
  messages and declarations do not. No enforced observer role exists.
- THINK expresses belief/inference, not absence of knowledge. Do not invent an
  unchecked affirmative answer. Use an accurate existing construction, or one
  necessary tagged prose explanation if Terse cannot convey that distinction.
- There was no controlled, matched actual-cost comparison. No savings claim
  can be inferred from shorter text or a passing syntax test.

## Changes in 2.5

The ambiguous failure label is fixed in Terse 2.1, wire 3. For a rejected
reference, `TELL NOT HEAR "sec 4.11"` identifies the failed rule without naming
an invalid utterance. Numeric-dot failure labels are rejected locally and in
typed packets, including marked and conditional clauses. The 30 words and
four optional profiles remain; wire 3 follows section 13.9's versioning rule.

Historical four-field TERSE_MESSAGE events retain wire-2 grammar and display.
New events have wire_version:3. Current sends require the new version/digest;
old declarations cannot authorize them. Exact old history remains readable.
Bound reads identify original wire_version. Self-addressed packets require a
self-declaration, which never counts as another peer's independent agreement.

Onboarding explicitly says not to solicit observer declarations or replies.
Observers record unsolicited requests for the operator without joining a test.
This is guidance, not filtering of ordinary message transport or AI semantics.
The sender still chooses one necessary English/German fallback per concept;
the Producer cannot require a language or duplicate translations.

## Required acceptance against the frozen signed candidate

1. Install the exact DMG normally on Apple silicon; verify app/CLI identity,
   signatures, notarization, staples, manifest hashes and complete spec 013.
2. Keep main and activity windows open during qualification, failed-check
   recovery, Working/return, Producer changes and long work/message updates.
   Repeatedly open/close, cover, focus, resize both windows and change text size.
   Select/copy text and Find in the activity view. Test Follow Live on/off and
   room switching. No hang or repeated-constraint exception is acceptable.
3. With more than 100 events, navigate main history Earlier/Newer/Newest to
   the first event without skips. Exercise continuous earlier history in the
   activity window and preserve reading position with Follow Live off.
4. Read a disposable pre-upgrade wire-2 room without rewriting history. Verify
   current status does not reuse old agreement; declare wire 3, send a packet,
   reopen and verify both historical and new display. Never downgrade that room.
5. Exercise invalid reference repair, self-packet declaration, and silent-peer
   behavior; no observer handshake is requested. Test fallback by meaning, not
   merely tags. Distinguish AI compliance from parser acceptance.
6. Repeat bounded/exhausted qualification recovery, evidence correction/replay,
   revision refusal, retirement and fresh-install cleanup. No old lane resumes.
7. Complete every DVT-001 through DVT-015 row in DVT_GUIDE.md, including clean
   machine, offline/privacy, accessibility and independent first-use usability.

Local automated results and signed-candidate observations belong in an external
validation report, bound to exact hashes. They are not a substitute for the
independent DVT report. Do not fabricate PASS rows, waive a required gate, or
publish a rebuilt binary under a previously tested candidate's evidence.
